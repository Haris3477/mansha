## What Mansha is
Mansha (Arabic منشأ, "origin") tells a UAE exporter whether a product qualifies for reduced or zero customs duty under a UAE CEPA, proves it with the agreement's own rules, and lists the steps to claim it, in English or Arabic. First corridor: UAE → India. Targets: the Create AI Agents Championship (Best Business AI Agent, Dubai Chamber of Digital Economy) and a December 2026 hackathon. It is a compliance product: a sentence an exporter could act on wrongly is a real defect.

Pipeline (`mansha/orchestrator.py`), each agent a separate LLM call through the router:
1. **Intake** (`mansha/intake.py`, chain `auto:qa`): JSON fields from the user's message; code normalizes them.
2. **Deterministic tools** (`mansha/tools/`, plain Python): tariff lookup, rule lookup, origin calculator (applies the rule to a bill of materials read only by code), duty estimate, certificate-of-origin fee. `mansha/evidence.py` builds the EVIDENCE block with record IDs.
3. **Researcher** (`mansha/researcher.py`, `auto:long`): picks the tariff line and states rates, rule, result; every item cites an evidence ID; unsupported → `REGULATORY_GAP_DETECTED`. Much of its output is then fixed and checked by code (run order in `run_researcher`).
4. **QA Evaluator** (`mansha/qa.py`, `mansha/qa_evidence.py`, `auto:judge`): scores meaning 0/1; code sets APPROVED / REJECTED; a KB shield overrules corrections that contradict the KB; one revision shared with the code checks.
5. **Document Builder** (`mansha/document_builder.py`, `auto:long`; Arabic: `auto:arabic`) writes prose; code renders the Markdown report (duty table, checklist, mandatory notes verbatim, sources, disclaimer); **prose check** (`mansha/prose_qa.py`, `auto:judge`); code-only report as the fallback.
6. **Report check** (`mansha/report_check.py`): flags mistakes of form in the finished report.

Other folders: `data/india/` (the knowledge base: `tariff_lines.json`, `psr_rules.json`, `passages.json`, `sources.json`; official sources only), `prompts/` (agent prompts, loaded by `mansha/prompts.py`), `scripts/` (tests, evaluation set `eval_set.py` / `eval_cases.py` / `eval_grade.py`, router tools), `samples/` (synthetic BOMs and saved outputs for tests), `docs/` (runbook, lessons, readings of live sittings).

## Domain rules (never break)
- Never invent HS codes, tariff rates, rules of origin, article numbers, fees, documents or timelines. A missing fact is `REGULATORY_GAP_DETECTED`, never a guess.
- LLMs never do arithmetic; every number comes from a tool.
- A fact repeated in prompts, KB notes or code must keep its qualifier ("likely", "reportedly", "interpretation"…); never turn a hedge into a plain fact.
- Knowledge-base changes come only from official sources and only when the prompt says so.
- Text the exporter reads never shows evidence IDs, internal field names or status codes.
- Principle: when a model keeps getting a fixed fact or number wrong, code writes it. Measure a new rule over the saved runs before shipping it, when the prompt asks.

## LLM backend (context only: you never call it)
- **FreeLLMAPI router**, self-hosted on Haris's Mac at `http://localhost:3001/v1` (OpenAI-compatible; Mansha uses the `openai` SDK through `mansha/llm_client.py`). Source in `~/Projects/freellmapi`; Haris starts it with `npm run dev`. Every agent call logs the serving model (`x-routed-via`). Every JSON answer is validated (parse + required keys).
- **Chains (named `auto:<chain>`, never plain `auto`):** `long` = Dots3 Note Preview (OpenRouter, free), Gemini 3.6 Flash, Gemini 3.5 Flash → Researcher, English Builder. `arabic` = Gemini 3.6 / 3.5 Flash only → Arabic Builder; if it fails, the code-only report (no Dots3 backup: its Arabic was corrupt). `qa` = GPT-OSS 120B on Groq → Intake. `judge` = GPT-OSS 120B on Cerebras → QA and prose check (shares no model with `long`). `trial` = Cerebras only.
- **Routing:** one global `smartest` order; a chain's priority only breaks ties. One provider 5xx makes the router skip the whole provider for that request, so `llm_client.py` resends `auto:arabic` after 3 s (`FAST_FAILOVER_WAIT_S`). Other waits, the busy budget and pacing (`auto:judge` at 4 requests / 60 s) live in `llm_client.py`.
- **Limits and credits:**
  - OpenRouter: Haris has bought ≥ 10 credits in total (27 Oct), so free models get **1,000 requests/day** (Dots3; OpenRouter counts every attempt per UTC day, reset 04:00 Dubai). The router's key has a $1 spend cap; free models cost $0. Router timeout for OpenRouter: 210 s.
  - Google Gemini (free): about 20 requests/day per model, but Google's quota is shared across the project; benched until Pacific midnight after a daily-quota refusal. 503 "high demand" is common.
  - Groq (free): Intake only. Cerebras: $5 trial credit (5 requests/min, 2,400/day), expires around 21–22 Nov 2026; Cerebras keeps no prompts.
  - Free models may log prompts: synthetic data only.
- Router facts are read by Claude with `scripts/router_facts.py` (read-only, never the `settings` or `api_keys` tables). Full backend design: the Project doc `llm_backend_setup.md` and its addenda (Claude has them; ask in your report if you need a detail).
